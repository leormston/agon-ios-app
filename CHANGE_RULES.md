# Change Rules

## Branch Strategy

- **No changes are pushed directly to `main`.**
- All work must be done on a new feature branch.
- Once the feature is considered working, push the branch and raise a pull request.
- Changes only merge into `main` via an approved pull request.

## Workflow

1. Create a new branch from `main` (e.g. `feature/description`).
2. Implement and test the changes on that branch.
3. Push the branch to the remote.
4. Open a pull request for review.
5. Merge into `main` only after the feature is confirmed working.
